  <name>Task 1: Implement Pool contract with AMM core, LP token, and security patterns</name>
  <files>src/core/Pool.sol</files>
  <action>
Create `src/core/Pool.sol` implementing the constant product AMM pool. Follow Uniswap V2 Pair architecture closely with educational comments explaining WHY each pattern exists.

**Contract structure:**
```
contract Pool is ERC20, ReentrancyGuard
```

**Imports (use OpenZeppelin v5.5.0 already installed):**
- `@openzeppelin/contracts/token/ERC20/ERC20.sol` — LP token base
- `@openzeppelin/contracts/token/ERC20/IERC20.sol` — token interface for transfers
- `@openzeppelin/contracts/token/ERC20/extensions/IERC20Metadata.sol` — for symbol() in name generation
- `@openzeppelin/contracts/token/ERC20/utils/SafeERC20.sol` — safe token transfers (handles non-standard tokens)
- `@openzeppelin/contracts/utils/ReentrancyGuard.sol` — nonReentrant modifier
- `@openzeppelin/contracts/utils/math/Math.sol` — Math.sqrt() for geometric mean

**State variables:**
- `address public immutable token0` — first token (sorted, smaller address)
- `address public immutable token1` — second token (sorted, larger address)
- `uint112 private reserve0` — token0 reserves (uint112 for storage packing, safe multiplication to uint224)
- `uint112 private reserve1` — token1 reserves (packed with reserve0 in single slot)
- `uint256 public constant MINIMUM_LIQUIDITY = 1000` — burned on first deposit to prevent inflation attack

**Constructor:**
- Takes `address _token0, address _token1` as parameters (per user decision: constructor, not initialize)
- Require `_token0 < _token1` to enforce canonical ordering (Factory ensures this)
- Auto-generate LP token name: `string(abi.encodePacked("SimpleDEX ", IERC20Metadata(_token0).symbol(), "-", IERC20Metadata(_token1).symbol(), " LP"))` (per locked decision)
- Auto-generate LP token symbol: `string(abi.encodePacked("SLP-", IERC20Metadata(_token0).symbol(), "-", IERC20Metadata(_token1).symbol()))` (per locked decision)
- LP token uses default 18 decimals (OpenZeppelin default, matches Uniswap V2)

**Events:**
```solidity
event Mint(address indexed sender, uint256 amount0, uint256 amount1);
event Burn(address indexed sender, uint256 amount0, uint256 amount1, address indexed to);
event Swap(address indexed sender, uint256 amount0In, uint256 amount1In, uint256 amount0Out, uint256 amount1Out, address indexed to);
event Sync(uint112 reserve0, uint112 reserve1);
```

**Public view function:**
- `function getReserves() public view returns (uint112 _reserve0, uint112 _reserve1)` — returns current reserves

**Core function: `mint(address to) external nonReentrant returns (uint256 liquidity)`**
- User must transfer tokens to the pool BEFORE calling mint (Uniswap V2 pattern)
- Calculate deposited amounts: `amount0 = balance0 - reserve0`, `amount1 = balance1 - reserve1`
- If first deposit (totalSupply == 0):
  - `liquidity = Math.sqrt(amount0 * amount1) - MINIMUM_LIQUIDITY` (per locked decision)
  - `_mint(address(0), MINIMUM_LIQUIDITY)` — permanently burn to prevent inflation attack
  - Add educational comment: explain WHY minimum liquidity is burned (inflation attack prevention)
- If subsequent deposit:
  - `liquidity = Math.min((amount0 * totalSupply) / reserve0, (amount1 * totalSupply) / reserve1)` (per locked decision: proportional deposits, takes minimum)
- Require `liquidity > 0`
- `_mint(to, liquidity)`
- Call `_update(balance0, balance1)` to sync reserves
- Emit `Mint(msg.sender, amount0, amount1)`

**Core function: `burn(address to) external nonReentrant returns (uint256 amount0, uint256 amount1)`**
- User must transfer LP tokens to the pool BEFORE calling burn (per locked decision: withdrawal by LP token amount)
- `liquidity = balanceOf(address(this))` — LP tokens sent to the pool
- Calculate proportional amounts: `amount0 = (liquidity * balance0) / totalSupply`, `amount1 = (liquidity * balance1) / totalSupply`
- Require `amount0 > 0 && amount1 > 0`
- `_burn(address(this), liquidity)` — burn LP tokens from pool
- Use SafeERC20 for transfers: `IERC20(token0).safeTransfer(to, amount0)`, `IERC20(token1).safeTransfer(to, amount1)`
- Get balances AFTER transfers, call `_update(balance0, balance1)`
- Emit `Burn(msg.sender, amount0, amount1, to)`

**Core function: `swap(uint256 amount0Out, uint256 amount1Out, address to) external nonReentrant`**
- Follow Uniswap V2 swap pattern exactly (per CONTEXT.md: follow Uniswap V2 as primary reference)
- CHECKS: Require `amount0Out > 0 || amount1Out > 0`. Require both `< reserves`. Require `to != token0 && to != token1`.
- Transfer output tokens using SafeERC20
- Calculate input amounts from balance differences: `amount0In = balance0 > (reserve0 - amount0Out) ? balance0 - (reserve0 - amount0Out) : 0`
- Require at least one input > 0
- Apply 0.3% fee check (per locked decision): `balance0Adjusted = balance0 * 1000 - amount0In * 3`, `balance1Adjusted = balance1 * 1000 - amount1In * 3`
- Verify invariant: `balance0Adjusted * balance1Adjusted >= uint256(reserve0) * uint256(reserve1) * (1000**2)` — this enforces x*y=k with fee
- Call `_update(balance0, balance1)`
- Emit `Swap(msg.sender, amount0In, amount1In, amount0Out, amount1Out, to)`
- Add educational comment: explain the fee mechanics — why `* 997 / 1000` works and how fees accumulate in reserves

**Helper function: `_update(uint256 balance0, uint256 balance1) private`**
- Require both balances fit in uint112: `require(balance0 <= type(uint112).max && balance1 <= type(uint112).max, "Pool: OVERFLOW")`
- Update reserves: `reserve0 = uint112(balance0)`, `reserve1 = uint112(balance1)`
- Emit `Sync(reserve0, reserve1)`

**Helper function: Add a public pure helper `getAmountOut(uint256 amountIn, uint256 reserveIn, uint256 reserveOut) public pure returns (uint256 amountOut)`**
- This is a convenience function for calculating swap output amounts externally (useful for frontend, tests, and slippage calculation)
- Require `amountIn > 0` and both reserves `> 0`
- Calculate: `amountInWithFee = amountIn * 997` (per locked decision: 0.3% fee from input)
- `numerator = amountInWithFee * reserveOut`
- `denominator = reserveIn * 1000 + amountInWithFee`
- `amountOut = numerator / denominator`
- Add educational comment: explain the formula derivation from x*y=k

**Use `using SafeERC20 for IERC20;`** at the top of the contract for safe token transfers (per research: don't hand-roll safe transfers).

**Educational comments:** Add clear comments explaining:
1. Why MINIMUM_LIQUIDITY is burned (inflation attack prevention)
2. Why CEI pattern is followed (reentrancy protection)
3. Why uint112 for reserves (storage packing, overflow safety)
4. How the 0.3% fee works in the invariant check
5. Why the geometric mean is used for initial LP tokens
6. Why proportional deposits use Math.min (protects pool from ratio manipulation)

**Do NOT include:** Price oracles (cumulative price tracking), sync()/skim() functions, flash loans, protocol fees, configurable fee rates. These are explicitly deferred per research recommendations.
