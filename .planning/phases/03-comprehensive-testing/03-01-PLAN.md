  <files>test/core/Pool.t.sol</files>
  <action>
Expand the existing Pool.t.sol test contract with additional tests. Keep existing 12 tests intact. Add new tests below them in organized sections. Use BDD naming convention (test_should_...) per locked decision. Inline setup in each test, no shared base contract.

**Swap tests (TS-01) — various input amounts and scenarios:**
- test_should_swap_small_amount: Swap 1e15 (0.001 token) and verify output is correct
- test_should_swap_large_amount: Swap 500e18 (50% of reserve) and verify output
- test_should_swap_with_asymmetric_reserves: Add 100e18 and 10_000e18 liquidity, swap 1e18, verify output
- test_should_swap_multiple_times_sequentially: Execute 3 swaps in sequence, verify each output is correct per getAmountOut
- test_should_swap_both_directions_in_sequence: Swap token0->token1 then token1->token0, verify reserves after both
- test_should_revert_swap_to_token0_address: Attempt swap with `to` = token0 address, expect revert "Pool: INVALID_TO"
- test_should_revert_swap_to_token1_address: Attempt swap with `to` = token1 address, expect revert "Pool: INVALID_TO"
- test_should_revert_swap_exceeding_reserves: Try to swap out more than reserves, expect revert "Pool: INSUFFICIENT_LIQUIDITY"

**Liquidity tests (TS-02) — LP token accounting:**
- test_should_mint_proportional_lp_for_equal_ratio: Two deposits at 1:1 ratio, verify LP proportionality
- test_should_mint_less_lp_for_imbalanced_deposit: Deposit at 2:1 ratio after 1:1 pool, verify Math.min logic gives less LP
- test_should_burn_proportional_tokens: Add liquidity, burn half LP, verify received amounts are ~50% of reserves
- test_should_burn_all_liquidity_leaving_minimum: Add liquidity, burn all user LP, verify only MINIMUM_LIQUIDITY remains at dead address
- test_should_revert_burn_with_zero_lp: Transfer 0 LP to pool, call burn, expect revert
- test_should_handle_multiple_lps: Two users add liquidity, verify each has correct LP share, burn each separately

**Invariant assertions (TS-06 unit-level) — add to swap and liquidity tests:**
Every swap test above must include this pattern after the swap:
```solidity
(uint112 r0After, uint112 r1After) = pool.getReserves();
uint256 kAfter = uint256(r0After) * uint256(r1After);
assertGe(kAfter, kBefore, "k should not decrease");
```

Every liquidity test that calls mint must verify:
```solidity
(uint112 r0, uint112 r1) = pool.getReserves();
assertEq(IERC20(token0).balanceOf(address(pool)), r0, "reserve0 matches balance");
assertEq(IERC20(token1).balanceOf(address(pool)), r1, "reserve1 matches balance");
```

Add a dedicated invariant verification test:
- test_should_maintain_k_invariant_across_mint_swap_burn: Full lifecycle (mint -> swap -> swap -> burn) with k assertion after each step.
