  <action>
**Step 1: Install Slither**
Check if Slither is installed: `which slither || pip3 install slither-analyzer`
If pip3 not available, try `pipx install slither-analyzer`.
Verify installation: `slither --version`

**Step 2: Create slither.config.json**
Create configuration that focuses on security-relevant findings for AMM contracts:
```json
{
  "detectors_to_exclude": "naming-convention,conformance-to-solidity-naming-conventions",
  "exclude_informational": true,
  "exclude_low": true,
  "exclude_optimization": true,
  "filter_paths": "lib/,test/,script/"
}
```

Rationale for configuration:
- `exclude_informational/low/optimization`: Reduces noise, focuses on medium/high severity
- `filter_paths`: Excludes third-party code (OpenZeppelin) and test files — only analyze our src/ contracts
- `naming-convention` excluded: Solidity naming in this project follows established patterns (MINIMUM_LIQUIDITY, DEAD_ADDRESS constants are intentional)

**Step 3: Run Slither**
Execute: `slither . --config-file slither.config.json`

**Step 4: Analyze findings**
- If NO high-severity findings: Document the clean result
- If high-severity findings exist: Analyze each finding:
  - If it's a genuine vulnerability: Fix the source code and document the fix
  - If it's a false positive: Add the specific detector to `detectors_to_exclude` with a comment explaining why
  - Re-run Slither after any changes to confirm clean output

**Key detectors to watch for AMMs:**
- reentrancy-eth, reentrancy-no-eth: Should be clean (we use ReentrancyGuard)
- unchecked-transfer: Should be clean (we use SafeERC20)
- divide-before-multiply: Check Pool.getAmountOut for precision issues
- incorrect-equality: Check invariant comparisons
- locked-ether: Check Pool doesn't receive ETH

**Step 5: Run Slither a final time to confirm clean output**
Execute: `slither . --config-file slither.config.json 2>&1`
Save output for documentation in SUMMARY.
