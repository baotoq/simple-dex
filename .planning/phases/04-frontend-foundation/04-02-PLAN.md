    1. Create `frontend/components/TokenBalances.tsx` — Displays WETH, MockUSDC, and LP token balances for the connected wallet:
       ```typescript
       'use client'

       import { useAccount, useReadContracts } from 'wagmi'
       import { formatUnits } from 'viem'
       import { erc20Abi } from '@/abi/ERC20'
       import { POOL_ADDRESS, WETH_ADDRESS, USDC_ADDRESS, WETH_DECIMALS, USDC_DECIMALS } from '@/lib/constants'
       ```

       Implementation requirements:
       - Use `useAccount()` to get connected wallet address
       - Use `useReadContracts` to batch ALL balance reads into a single multicall:
         * WETH balanceOf(address)
         * MockUSDC balanceOf(address)
         * Pool (LP token) balanceOf(address)
       - Gate the query with `query: { enabled: !!address && WETH_ADDRESS !== '0x0000000000000000000000000000000000000000' }` — prevents reads when wallet disconnected or contracts not deployed
       - Use `formatUnits(balance, decimals)` from viem for human-readable display (WETH: 18 decimals, USDC: 6 decimals, LP token: 18 decimals since Pool inherits ERC20 default)
       - Show loading state: "Loading balances..." with subtle animation (e.g., `animate-pulse`)
       - Show disconnected state: "Connect wallet to view balances"
       - Show not-deployed state: "Contracts not deployed yet" when addresses are zero
       - Show error state: "Failed to load balances" with error.shortMessage if available
       - Display in a clean card layout using Tailwind:
         * Card with `bg-white rounded-lg border border-gray-200 p-6 shadow-sm`
         * Title "Token Balances" as h2
         * Each token on its own row with symbol and formatted balance
         * Format balances to reasonable precision (4 decimal places for WETH, 2 for USDC, 4 for LP)
       - Use semantic HTML: `<section>`, `<h2>`, `<dl>` or `<table>` for balance data

    2. Create `frontend/components/PoolStats.tsx` — Displays pool reserves and exchange rate:
       ```typescript
       'use client'

       import { useReadContracts } from 'wagmi'
       import { formatUnits } from 'viem'
       import { poolAbi } from '@/abi/Pool'
       import { POOL_ADDRESS, WETH_DECIMALS, USDC_DECIMALS } from '@/lib/constants'
       ```

       Implementation requirements:
       - Use `useReadContracts` to batch pool reads:
         * Pool getReserves() -> (uint112 reserve0, uint112 reserve1)
         * Pool token0() -> address
         * Pool token1() -> address
         * Pool totalSupply() -> uint256
       - Gate query with `query: { enabled: POOL_ADDRESS !== '0x0000000000000000000000000000000000000000' }`
       - Calculate exchange rate: since token0 is the lower address (could be WETH or USDC depending on sort order), the component should determine which token is which by comparing token0/token1 addresses against WETH_ADDRESS/USDC_ADDRESS from constants
       - Display BOTH directions: "1 WETH = X USDC" and "1 USDC = Y WETH"
       - CRITICAL decimal handling: WETH=18 decimals, USDC=6 decimals. Exchange rate = formatUnits(reserveUSDC, 6) / formatUnits(reserveWETH, 18). Getting this wrong produces absurd numbers.
       - Show loading state: "Loading pool data..." with `animate-pulse`
       - Show not-deployed state: "Pool not deployed yet"
       - Show empty pool state: "Pool has no liquidity" when both reserves are 0
       - Display in a card layout matching TokenBalances style:
         * Reserve0 with token symbol and formatted amount
         * Reserve1 with token symbol and formatted amount
         * Exchange rates (both directions)
         * Total LP supply
       - Use semantic HTML: `<section>`, `<h2>`, `<dl>` or labeled values

    Design consistency: Both components should use the same card style, heading treatment, and spacing. Use a consistent color palette: gray-50 bg, white cards, gray-900 text, gray-600 secondary text.

    1. Create `frontend/components/TxStatus.tsx` — Transaction status feedback component:
       ```typescript
       'use client'

       import { useWaitForTransactionReceipt, type BaseError } from 'wagmi'
       ```

       Implementation requirements:
       - Accept `hash` prop of type `` `0x${string}` | undefined ``
       - Use `useWaitForTransactionReceipt({ hash })` to track transaction status
       - Display appropriate status messages with visual indicators:
         * No hash (null/undefined): render nothing (return null)
         * Pending/Confirming (`isLoading` or `isConfirming`): Yellow banner with "Transaction submitted, waiting for confirmation..." and a spinner or pulse animation
         * Confirmed (`isSuccess` or `isConfirmed`): Green banner with "Transaction confirmed!" and checkmark icon
         * Error: Red banner with "Transaction failed: " + `(error as BaseError).shortMessage` fallback to error.message
       - Use Tailwind for status colors:
         * Pending: `bg-yellow-50 border-yellow-200 text-yellow-800`
         * Success: `bg-green-50 border-green-200 text-green-800`
         * Error: `bg-red-50 border-red-200 text-red-800`
       - Include role="status" and aria-live="polite" for accessibility (screen readers announce status changes)
       - This component is infrastructure for Phase 5+ (swap transactions). In Phase 4 (read-only), it will not be actively used but must be buildable and importable.
       - Also export a simple `QueryStatus` component that accepts `isPending` and `error` props for displaying read query states. This is what Phase 4 components can use for their loading/error states.
